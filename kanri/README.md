# 管理画面

ブラウザから中身を更新するための画面です。2つあります。

| 画面 | できること |
|------|-----------|
| `index.php` **写真の入れ替え** | すでにサイトに置いてある写真を、別の写真に差し替える |
| `works.php` **施工例の登録** | 施工例を新しく増やす・書き換える・消す |

どちらも HTML を触りません。画面の上の帯から行き来できます。
帯の右側の「サイトを見る ↗」「施工例のページ ↗」は、別のタブで開きます。
編集の手を止めずに、見え方を確かめられます。

## 編集画面へ入るには

ホームページのいちばん下（コピーライトの右）に **「関係者用」** の小さな
リンクがあります。押すとこの画面へ来て、さくらのパスワードを聞かれます。

お客様の目に触れる場所ではありますが、`/kanri/` の場所は `robots.txt` にも
書いてあり、そもそも隠せるものではありません。**守っているのはパスワード**です。
アクセス制限を必ず設定してください。

リンクを消したい場合は、`index.html` の `footer__admin` の行を削れば消えます。
その場合は `https://（ドメイン）/kanri/works.php` をブックマークしてお使いください。

# 1. 写真の入れ替え（index.php）

## 何ができるか

- サイト内の写真枠を自動で一覧表示（HTMLを読んで探すので、ページが増えても勝手に増えます）
- 「仮画像」「差し替え済み」がひと目で分かる
- 写真を選んでボタンを押すだけで差し替え
- **押しても画面は読み込み直されません。**一覧の途中で押しても
  見ている位置は動かず、結果はその枠のすぐ下に出ます
- iPhone の写真の回転を自動で直す
- **目標の容量に収まるまで、自動で軽くします**（下記）
- 差し替える前の写真は `_backup/` に日時つきで残る

## 保存する大きさ

写真1枚ごとに、どこまで軽くするかを選べます。

| 選択肢 | 幅 | 目標の容量 |
|--------|-----|-----------|
| 大きく | 2000px | 600KBまで |
| **ふつう**（既定） | 1600px | 300KBまで |
| 小さく | 1200px | 150KBまで |
| とても小さく | 900px | 80KBまで |

幅を詰めるだけでなく、**目標の容量に収まるまで少しずつ圧縮を強めます**。
写真によって「同じ画質でも容量が全然ちがう」ため、画質を決め打ちにすると
重い写真が重いまま残ってしまうからです。

画質を落としすぎると見て分かるほど荒れるので、そこで打ち切ります。
目標に届かなかった場合はその旨を表示するので、ひとつ下の大きさを
お試しください。

一覧の上の欄で、**すべての枠をまとめて**変えることもできます。

**迷ったら「ふつう」で構いません。** ページの表示が遅いと感じたら
「小さく」にしてみてください。

差し替えたあとは「1600×1200／292 KB（前は 3.9 MB）」のように、
前後の容量が出ます。

線画のアイコン（`assets/icons/`）は編集対象に含みません。

## サーバーにある写真から選ぶ

手元のパソコンから選ぶほかに、**「サーバーの写真から選ぶ」**が使えます。
一度アップした写真を、もう一度アップし直さずに別の場所へ持ってこられます。

- 施工例に登録した写真を、サービスの紹介写真にも使う
- 同じ写真を、いくつかの枠で使い回す

押すと写真が並ぶので、選ぶだけです。「施工例の写真」「サイトの写真」で
絞り込め、ファイル名でも探せます。**グレーの仮画像は初めから隠して**あります
（「仮画像も出す」で出せます）。

選べるのは `images/` と `works/photos/` の中だけです。それ以外の場所は、
どんなパスを送っても受け付けません。

## 戻したいとき

`kanri/_backup/` に `images_service-new.jpg.20260728-141530.bak` の形で
残っています。FTPで拡張子を `.jpg` に戻し、元の場所へ上書きしてください。

# 2. 施工例の登録（works.php）

## 何ができるか

- **ホームページに載せるかどうかを、スイッチで切り替えられます**
  （登録しただけで公開しない、あとから引っ込める、どちらもできます）
- 1件につき写真を何枚でも登録できます。クリーニングの「施工前／施工後」など
- 写真には説明をつけられます（「施工前」「施工後」など）
- 順番を入れ替えられます。**1枚目が一覧に出る写真**になります
- 2枚以上あると、ホームページのカードに**左右の矢印**が出ます。
  お客様はその場で施工前・施工後を見比べられます。
  写真を押せば大きく表示され、そこでも送れます
- あとから書き換え・削除ができます
- 写真は手元のパソコンからでも、**サーバーにすでにある写真からでも**選べます

入力するのは4つです。**それぞれホームページのどこに出るか**は次のとおりです。

| 項目 | 例 | どこに出るか |
|------|-----|------------|
| 分類 | クリーニング | 一覧のカードの右下。絞り込みボタンにも使う |
| 石種 | 庵治石 | 一覧のカードで、写真のすぐ下 |
| 一言 | 黒ずみと苔を落とし、文字の色を入れ直しました。 | 一覧のカードで石種の下。写真を大きく表示したときにも出る |
| **管理用メモ** | 山田様／2026年7月20日施工／○○霊園 3区12番 | **どこにも出ない** |

石種と一言は、どちらも空のままで構いません。空にした欄はその場所ごと出ません。

## 掲載する／しない

登録の画面に **「ホームページに掲載する」** のスイッチがあります。初めから入って
いるので、そのまま登録すればすぐ公開されます。

外して登録すると、**データだけ保存されてホームページには出ません。**
写真の写り込みやお名前を確かめてから公開したいときにお使いください。

登録済みの一覧では、**緑の「掲載中」／灰色の「非公開」**の札が付きます。
非公開のものは行ごと灰色になるので、遠目にも見分けられます。

**「掲載をやめる」「掲載する」**のボタンで1押しで切り替わります。
画面は読み込み直されないので、**一覧の途中で押しても見ている位置は動きません。**
結果はその施工例のすぐ下に短く出ます。

非公開にしても写真もデータも残ります。消えるのはホームページの表示だけです。

画面の上に「ホームページに掲載中 ◯件／非公開 ◯件」と出ます。

## 管理用メモについて

お施主様のお名前・施工日・霊園名など、**登録するときの確認に使う欄**です。
ホームページには一切出ません。この画面でしか見えません。

入力欄は灰色の枠で囲ってあり、「サイトには出ません」の札を付けてあります。
公開される欄と見間違えないようにしてください。

### 外から見られないようにしてあること

お名前を持つことになるので、二重に守ってあります。

1. データの入れ物は `works/works.json.php` という名前で、中身の先頭に
   `<?php exit; ?>` を1行入れてある。URLを直に叩かれても、PHPとして
   実行されて何も出力されない
2. `works/.htaccess` で `.json` `.php` を外から読めないようにしてある

どちらか一方が効かなくなっても、もう一方が守ります。

## どう動いているか

施工例そのものは `works/works.json.php` に入っています。
登録・書き換えのたびに、そこから次のページを**HTMLとして書き出します**。

- `works.html` … 施工例の一覧（絞り込み・ページ送り付き）
- `boseki.html` / `cleaning.html` / `jishin.html` / `reform.html` / `coating.html`
  … それぞれのページの下にある「施工例」を、新しい順に4件

書き出す場所は、HTMLの中に目印ではさんであります。

```html
<!-- WORKS:START cleaning -->
   …ここが自動で入れ替わる…
<!-- WORKS:END cleaning -->
```

**この目印を消さないでください。** 消すと、そのページには書き出されなくなります。

つまり、お客様が見るページは今までどおり**静的なHTMLのまま**です。
PHP が動くのは、従業員が登録操作をしている数秒間だけです。

## 「ページを作り直す」ボタン

ふだんは押す必要はありません。

**ホームページのデザインを更新した直後に、一度だけ押してください。**
`deploy.sh` はページを丸ごと入れ替えるので、施工例の部分が手元の（古い）内容に
戻ってしまいます。このボタンで `works.json.php` から書き直せば元に戻ります。

## 写真ライブラリの覚え書き

サーバーの写真を並べるとき、「グレーの仮画像かどうか」を写真1枚ずつ
開いて調べています。枚数が増えると待たされるので、結果を
`kanri/_libcache.php` に覚えさせています。

- 自動で作られます。消しても、次に開いたときに作り直されます
- 写真を差し替えれば自動で調べ直します（更新日時と容量で見ているため）
- 外からは読めないようにしてあります
- Git には入れません（サーバーごとに中身が変わるため）

## 写真はどこに入るか

`works/photos/` の中に、`20260803-142530-1-a1b2c3.jpg` の形で入ります。
`kanri/` の「写真の入れ替え」画面には出てきません（施工例の写真は
`works.php` 側で管理するため）。

施工例を削除すると、その写真も一緒に消えます。控えは残りません。
**消す前に、必要なら手元にダウンロードしておいてください。**

# 設置（さくら・初回のみ）

1. `kanri/` フォルダーごと `www/` の直下にアップロードする
   （`index.php` / `works.php` / `save.php` / `lib.php` / `works_lib.php` /
   `library.php` / `picker.js` / `admin.css` / `.htaccess` / `.user.ini`）

2. `works/` フォルダーもアップロードする
   （`works.json.php` / `.htaccess` / `photos/.htaccess`）

3. **パスワードをかける**
   さくらのコントロールパネル →「アクセス制限」で `kanri` フォルダーに
   ユーザー名とパスワードを設定します。
   ※ 設定していないと画面上部に赤い警告が出ます。必ず設定してください。

4. 書き込み権限を与える（755 または 775）
   - `images/` … 写真の入れ替えで使う
   - `works/` と `works/photos/` … 施工例の登録で使う
   - `works.html` `boseki.html` `cleaning.html` `jishin.html` `reform.html`
     `coating.html` … 644 のままで構いませんが、書き込めないと
     「ページの書き出しに失敗しました」と出ます

5. `https://（ドメイン）/kanri/` を開く

## アップロードの上限（PNG が弾かれるとき）

PHP の初期設定は **1枚あたり 2MB** しかありません。
**PNG は同じ写真でも JPEG の3〜8倍の容量になる**ので、
「JPEG は通るのに PNG だけ登録できない」ということが起きます。

これを避けるため、`kanri/.user.ini` を同梱してあります。

```ini
upload_max_filesize = 20M
post_max_size = 88M
memory_limit = 256M
max_execution_time = 120
```

`kanri/` フォルダーごとアップロードすれば一緒に入ります。
**さくらでは反映まで数分かかります**（PHP が5分ほど内容を覚えているため）。
すぐに変わらなくても、少し待ってからお試しください。

施工例は一度に4枚まで送れるので、`post_max_size` は
`upload_max_filesize` の4倍以上にしてあります。

うまくいかないときは、画面に出るメッセージをご覧ください。
「写真が大きすぎます（1枚あたりの上限 ◯◯）」のように、
いまの上限がそのまま表示されます。

FTPソフトによっては `.user.ini` のような**ドットで始まるファイルが
見えない**ことがあります。「隠しファイルを表示」の設定をご確認ください。

# 大切なこと — 転送で消えないように

写真も施工例も**さくら側が正**です。`deploy.sh` は次を転送対象から
外してあるので、サイトを更新しても消えません。

- `images/` … 差し替えた写真
- `works/` … 登録した施工例とその写真
- `kanri/` … 管理画面そのもの

逆に言うと、**git 側の `images/` と `works/` は古いまま**になります。
手元にも残したい場合は、FTPで落として commit してください。

`works.html` と各サービスページは**転送されます**。だから転送のあとに
「ページを作り直す」を一度押す必要があります。
